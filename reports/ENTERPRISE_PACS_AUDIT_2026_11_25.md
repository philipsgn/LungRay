# Enterprise PACS audit and single-checkpoint deployment

Audit target: a23b7bc. Review date: 25 November 2026.

## Frontend findings and remediation

1. Critical: Edge fallback generated diagnoses from filenames, simulated latency, lung-energy ratios and spatial overlays without a model. These have been removed. Offline fallback is explicitly unavailable and blocks interpretation/sign-off; transparent heatmap and contour PNGs encode absence of an explanation. Safety values in the required numeric schema are unmeasured placeholders disclosed in rejection reasons.
2. Critical: Edge RAG ignored false is_safe and generated generic clinical cards. It now returns BLOCKED_OOD before any interpretation; otherwise an unavailable backend yields no retrieved guidance.
3. API types: ModelInfo now matches backend role/metrics. Prediction and explanation responses expose optional inference_source. Network errors, abort timeouts and HTTP 503 invoke fallback; HTTP 422 is propagated for user correction. CPU prediction/explanation requests allow 120 seconds before timeout.
4. CTR: absolute cardiac width divided by max(0.1, absolute thoracic width); short strokes are rejected. All mouse phases on the bottom toolbar stop propagation. Both Split View image panes use identical filter/zoom. A new image resets the viewer/calipers.
5. Worklist: priority and normalized query are combined with AND; query matches study ID, patient ID or indication. AI Screened follows a real backend response. Unavailable responses retain Pending. Approval requires accepted/unblocked analysis; a new analysis invalidates prior approval. Case and explanation generation guards discard stale results after a study switch.
6. Audit CSV: all fields escape embedded double quotes, including model/study identifiers. The audit trail and approval timestamp are local session records; authentication, durable storage and signed document verification are outside this implementation.
7. Atlas: PACS navigation uses root-relative slash; no localhost:3000 URL remains.

## Backend and Space configuration

The Enterprise PACS audit of commit a23b7bc found filename-driven simulated predictions/localization in the offline fallback and a missing RAG OOD check. The fallback now returns a blocked UNAVAILABLE result with no active findings, no diagnostic probabilities for Head A, no positive flags, no claimed energy measurements, and transparent RGBA placeholders for heatmap/contour. A false safety context returns BLOCKED_OOD with no cards. HTTP validation/authentication errors remain errors; network/timeout/server failures return the unavailable contract. The browser model selector follows the backend registry. CTR uses absolute widths with a guarded denominator; the floating toolbar stops mouse down/move/up propagation. Split panes share filter and zoom. CSV quotes are escaped in every field. Local demo approval requires an accepted, non-blocked result; a changed/reanalyzed case invalidates approval and stale async responses are discarded. Worklist states represent local session activity, not durable authenticated electronic signatures or an immutable audit system.

The Standard-only serving profile accepts checkpoints/best_model_20_11.pth (28,462,839 bytes; 27.14 MiB), exposes only the available Standard model, and skips optional segmentation/specialist weights. Default auto mode also tolerates absent AG-MTCNet weights. Missing models are not relabeled Standard. Morphology localization is disclosed as approximate with audit_pass=null. Dockerfile.hf, its context allowlist, requirements.hf.txt and deploy/hf/start.py prepare a CPU Docker Space on port 7860. Startup downloads the exact file from HF_MODEL_REPO only if absent and verifies SHA-256 against the dated threshold artifact before model loading; HF_TOKEN is a runtime secret and HF_MODEL_REVISION may pin the source. Wildcard anonymous CORS is enabled without credentials. No Space was published and no CPU latency or clinical performance claim is added.
